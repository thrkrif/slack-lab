# M24.5a 임베딩 스파이크 (3단계, 2026-10-04)

목적: 3단계 설계가 기대는 사실을 코드 없이 먼저 확인한다 — Ollama가 OpenAI 호환 `/v1/embeddings`를 지원하는가, bge-m3의 차원, 모델이 내려간 상태(콜드)와 올라간 상태(웜)의 소요 시간.

환경: Ollama 0.34.0 호스트 실행, `bge-m3:latest`(pull 크기 1.2GB), Apple Silicon 노트북, 컨텍스트 4096(기본). 측정은 `curl` 단발이며 통계적 의미는 없다(판정 근거가 아니라 설계 입력).

| 항목 | 결과 |
|---|---|
| `POST /v1/embeddings` (OpenAI 호환, `{"model","input"}`) | 200, 응답 `data[0].embedding`, `usage.prompt_tokens` 포함 |
| 배열 입력(`input: ["a","b"]`) | 200, 2건 반환 |
| 차원 | **1024** |
| 정규화 | L2 노름 1.0 (코사인 거리 = 내적으로 환산 가능) |
| 없는 모델 | 404 `model "nope" not found, try pulling it first` (`error.code=404`) |
| 콜드(모델 내림 직후) 소요 | 2.19s, 1.18s, 1.37s |
| 웜 소요 | 0.05~0.06s (3회), 2건 배치 0.09s |
| 적재 메모리 | `ollama ps` 기준 673MB, 기본 keep_alive 5분 |

판단:
- 지원됨 → 계획대로 진행(멈춤 조건 해당 없음). 임베딩 어댑터는 OpenAI 호환 스키마 그대로 쓴다.
- 차원 1024는 `vector(1024)` 고정 또는 무인덱스 `vector`의 입력값이다. 모델 ID·차원은 설정 필수값으로 받는다.
- 콜드 최대 2.2s는 검색 상한 5s 안에 들어온다(채팅 모델이 같이 적재돼 메모리 경합이 있을 때는 M30에서 다시 잰다 — 이번에는 qwen2.5:7b가 적재되지 않은 상태).
- 모델 오류는 404 JSON이라 "모델 없음"을 시작 시점에 구분해 기동 검사에 쓸 수 있다.
- 한계: 청크 길이별 시간, 동시 요청, 채팅 모델 동시 적재, nomic-embed-text는 측정하지 않았다(M30).

정리: 측정 뒤 `ollama stop bge-m3`로 내렸다.
